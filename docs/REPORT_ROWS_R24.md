## 模块、数据流与锁

```text
腾讯原始ledger（不改写）
  → domain/report/rows + 共用几何表格投影
  → reportRows：整表项目、来源、原始快照
  → features/report_rows + app/report_editor：逐项核对
  → domain/report/contract：版本、来源与派生投影校验
  → 原RecordService暂存→明确确认→同一个RecordStore事务保存
  → 详情 / 同库新进程读回 / 原加密备份恢复
```

解析、原件Hash、来源复算和加密均在IDB事务之外。没有新增全局锁、Store、网络调用、轮询、缓存、队列或依赖。既有事务和请求取消/代次保护保持；main只接线，解析与模板各自独立。

原DICTIONARY定义原样搬到新fields模块，并由model重导出，避免新模块引入大循环。已有18种指标、别名和规则版本不扩大。原v1/v2黄金、规则oracle和保护反例继续验证。

## 新契约与兼容

记录显式使用 `ptds-browser/3`、字典标识 `cbc-report/1`。`payload.reportRows` 是报告项目权威集合；`manualObservations` 表示明确追加的手填指标；`observations` 是二者的可校验派生投影，不单独编辑。校验拒绝两份内容不一致、新字段伪装旧版、未核对行、来源替换和伪造识别快照。

报告行包含 `name / valueLiteral / unit / comparator / referenceRange / abnormalFlag / sourceLineIds / origin / checked`，已有指标另保留兼容的 `ocrOrigin`。只有名称、数值和单位明确支持的项目才进入原医学指标集合。空结果仅允许存在于原始待核对快照，保存前当前结果必须补齐。

不修改IDB名称、对象仓或版本，不迁移用户数据。备份继续使用原有格式3的有序AES-GCM分帧；含新记录时manifest显式标schema3，旧读器会拒绝该schema，不能静默丢弃整表。新读器仍支持原格式1/2和旧格式3；恢复复算报告来源及派生投影，不恢复未完成录入、问诊草稿或保存授权。
