# R33：全部已整理OCR项目接入状态——隔离候选自查

本轮直接用户要求：“之前OCR过的众多数据项需完成录入，并在状态中展示；先自查，待完备后交审计”；并允许参考Astra实现。由此将原T1停点调整为完整隔离候选统一自查后交审，不修改已采用产品、不提前上线。菜单为 **预警｜状态｜录入｜本机**。

## 解决的实际缺口

原整表保存以schema3的`reportRows`为权威，已支持字典外项目；但原T1只读18项`observations`，会再次把整表压回少量指标。本轮状态读取**全部reportRows + 明确追加的manualObservations**，不会与派生observations双计；旧schema1/2继续读取原observations。

状态按指标身份与单位分组，每张卡可查看每次结果、变化、各份报告自己的参考信息和来源。点击来源会打开既有正式记录，并定位对应报告行；返回保留指标和当前页。三医学规则保持原算法、版本及原输入集合，没有把新增报告项目偷偷加入预警计算。

| 第三批腾讯有效缓存 | 15份 | 不含第16次不确定响应和未尝试项 |

| 合计 | 299份缓存 | 允许原图重复/同图多种OCR，不是299张唯一图片 |

投影初次状态统计：777精确数值、38界限值、41文字结果、391待核对。391个空结果既不是“丢项”，也不是已经完成有效入库；UI要求用户对照原图补齐后再确认。原文/原图仍按原流程保留。**本轮没有声称全部OCR片段都是检验项目、全部278图腾讯识别完成或医学真值已校对。**

另对137份报告、1247行实际运行现有保存payload/来源绑定校验：81份无需测试补值；其余用明确的虚构值`1`替代391个空结果，仅作自动化测试操作员补录。之后1247行全部通过校验并可投影至状态。没有把该虚构补值加入产品算法、没有保存真实病程、没有冒充用户/临床确认。这组是保存校验，不是完整浏览器入库，也不证明原图图像质量；source仅为测试占位文件。

随后补做实际临时库回放：137份含项目缓存逐份经现有`RecordService.source→stage→confirm→save`，分页读回全部1247行/1247状态点，加密备份恢复一致，再真正退出并由不同PID同库读回。自动测试操作员明确补入391个虚构结果，使用虚构日期与占位PNG；未直插库，恢复不重放核对权限。该回放证明保存/状态/恢复的工程链路，仍不证明原图、真实日期、临床真值或本人确认。公开摘要`corpus-replay-summary02.json`，私有原始输出另存，不随包。首次准备因probe仅接受字符串配置而退出，原失败保留；改为JSON字符串传参后新目录完整通过，产品字节未改。

实际产品浏览器闭环另用纯虚构30项表、两份不同日期：27项血常规、铁蛋白、尿蛋白定性和新项目。执行真实页面选图、模拟OCR、修改RBC、逐项勾选、最终确认、事务保存→30组/60点状态→卡片分页→数值差→选定来源行→返回→按日期筛选→加密备份恢复→真正不同PID同库读回。不通过直接插库或恢复时重放确认完成测试。

公开只留计数、Hash及虚构结果；原缓存文字、私有名字/数值/坐标和逐输入结果留在`runtime/r33-ocr-state01`，不入Git或公开候选归档。

## 对应规则：哪些合并，哪些不合并

- 原18项兼容原code；新增血常规/生化/凝血等仅增加**展示身份别名**，不扩写医学wire字典。版本为`report-metric/1`。
- 明确名称/缩写可归到同一身份，例如RBC/红细胞、MCV/平均红细胞体积。百分比与绝对计数分开；PCT的血小板压积与降钙素原由明确名称和单位分别对应。脑脊液AST不会按名称片段硬归为血清AST。
- 未知或损坏名称也保留卡片和来源，按报告原名对应并提示核对，不模糊猜词、不剥掉疑似结果尾数。需要在原录入核对环节修正名字和单位后，才可与正确标准项目归并。不能保证未经用户核准的错误OCR名称与真实医学项目自动精准对应。
- 单位仅统一明确的计数单位字形，其余不同单位分组；没有跨单位数值转换，FEU/DDU不混。每份参考范围独立展示，并复用原“待核对/未提供”质量提示，不画统一正常带。
- 所有同日多次结果保留。无精确时刻或同刻重复标冲突，不凭ID挑最新；报告页跨在同一天中间时，也明确按未完整日期处理，避免分页制造“唯一最新”。
- 带比较符为界限，阴阳性等为文字历史，未知/空结果为待核对；三者不作为精确折线和差值。缺项断段，不补零、不插值、不沿用前值。折线横轴按实际日期/时刻，差值用既有Decimal；绘图像素使用Number不作医学阈值判断。

## 模块、锁与规模

```mermaid
flowchart LR
 A[既有Store正式events] --> B[metric_read同事务读取revision+50份记录]
 B --> C[metricRows取整表权威行]
 C --> D[identity精确别名/原名+单位]
 D --> E[series保留全部点/冲突/断段]
 E --> F[MetricsFlow核对代次与revision]
 F --> G[复用state-card的状态卡/详情]
 G --> H[原记录/原图来源入口]
```

没有新存储引擎、对象仓、DB版本、保存协议、后台任务、计时器、网络调用、全局锁或依赖。查询仅请求meta/events只读事务，不读sources Blob；投影/身份/绘图在事务外，UI过时代次不发布。离页清理引用，旧请求不能重绘。身份词表为固定常量，不建无限缓存。

每页最多50份已保存记录，卡片24组/页；更早报告和日期筛选可访问全历史，搜索范围明确为本页。日期跨页时不装成完整当日。单图最多200精确点，明确提示最近200；每次原始记录50条/页可继续查，不静默降采样。不是一次把20k×100个观测都装入DOM。原件只在用户打开原记录时读。

Astra仅读取`app/web/live/state_card_trends.js`、`vital_sign_cards.js`、`app/web/catalog/metric_names.entries`与相邻指标分组作为卡片布局/命名参考；没有移植其API、全局状态、localStorage、SQLite或后台轮询。实现位于003隔离候选，不依赖Astra运行。
