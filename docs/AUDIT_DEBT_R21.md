## 检查清单

1. **职责与增长**：逐文件看职责和实际字节，不靠压缩行数判断。main 只能接线，不能重新接管图片生命周期、证据计算、存储或解析；别名、来源验证、视图、资源 owner 应分离。检查 import 环、重复来源权威、过度抽象或第二套 Store。
2. **资源归属**：每个编辑器最多一个预览 URL；AbortController、图片回调、原文索引和当前行引用是否由同一 owner 持有。逐例验证换图、换项、移除当前项、页内导航、保存、草稿导航、pagehide、返回缓存页、图片解码失败、重开。释放不能只撤销 URL 而继续持有旧原图/原文闭包；迟到图片回调不得覆盖新来源。检查显式本机重开与付费请求重试是否被混为一谈。
3. **一致性与完整性**：原候选快照与修改后值必须分开；持久化摘要和来源绑定一起覆盖快照。防旧响应、跨来源引用、重复引用、伪造原值和摘要不一致；旧无快照记录不能被新版本补造证据。检查确认失效、CAS、一次 commit、崩溃/配额失败与备份恢复边界。不能通过放宽验证来兼容新字段。
4. **锁与后台工作**：不新增全局锁、后台轮询、缓存、Store 或自动写重试。原预算短锁、HTTP 16 槽和 IDB 事务有不同一致性责任，不能为“去锁”直接删除。长网络和图片工作不得放入预算锁/写事务，预览不得偷偷读写服务器病历或产生费用。
5. **规模与空间**：原 100 候选、20k OCR 行、原图字节/像素与业务容量不变；来源索引最多有界建一次，单项最多有界引用，输入变化不能重复扫描 20k 行。检查原 2k→20k 解析门槛及新增索引测试；不能照搬上游 O(n²) 斜拍循环。万条状态/问诊/备份和 64MiB 原图回归按原数字检查，不拼不同窗口；区分缓冲逻辑上限与真实手机峰值内存。
6. **错误与安全显示**：缺/错坐标不伪造框，原文缺失不找相似行补齐；图片失败后无泄漏或无限重试。原文、原值、代码和单位须安全转义；SVG 仅使用校验后数值，Blob URL 不离开本机，不把私有图片/响应写进仓库、截图附件或公开日志。公开响应的无凭据字段不等于其正文无健康信息。
7. **验证可信性**：新用例必须在 package 和实际必需计划中；当前源码/测试/工具/输入配置/探针二进制都要绑定。变异应由行为断言杀死，保留未变异对照；补丁套用需逐项集合、数量、Hash/null 不存在项检查，不能返回 0 就算成功。原失败、修复、停止点和换窗口原因完整保留。
8. **采用与回退**：完整验证后才原子换静态目录，原网关 PID、绝对到期、预算和旧 ZIP 不变；不同版本静态资源或旧 SW 客户端的边界明确。确认旧 web 和非 web 原字节回退材料、采用后准确清单/HTTP 身份、无新真实调用。不得把单个 GET 正确升级为首次加载稳定。
