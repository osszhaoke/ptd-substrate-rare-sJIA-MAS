## 模块、数据流和锁

```mermaid
flowchart LR
  A[既有Store权威events] --> B[T2 同一只读事务取记录和revision]
  B --> C[T1 事务外纯序列投影]
  C --> D[T2 视图代次核对]
  D --> E[T3 状态单指标卡/变化]
  E --> F[既有记录/来源入口]
```

T1无锁、网络、Store、计时器、缓存或后台任务。T2拟复用现有Store，不新增数据库/Store/存储版本，事务内不做计算/加密/绘图。控制器独有请求代次与取消路径，不添加全局锁或轮询。主入口不承载图表/领域计算；原大文件不增职责。

规模：T1最坏按输入观测数P排序O(P log P)，保留结果O(P)，不丢点、不降采样。沿用最多20000记录、每记录100观测上限；极端上限仍可能很大，本次只测每记录1观测，不证明极端内存安全。T2必须限定分页/窗口，不能每次页面导航读所有原图Blob。T3绘图点上限/分页策略开工前冻结，不允许为了视觉伪造或补齐点。T4原冷p95≤1000ms、暖≤250ms不变；本次投影诊断不等于这些端到端门槛通过。

## T1数据契约与边界

输入`projectMetricSeries(snapshot,{nature,zone,codes?})`，snapshot含revision、events、完整已检查临床日期dates与next。日期必须覆盖本页相应nature/zone的事件。仅受支持schema/1、/2、/3正式事件投影；不再次做提交或权限判断，也不把它用于验证入库。快照调用者负责保证来自既有权威正式记录。

- 固定code身份，仅当前18项；不按相似名称硬合并。MCV/RBC等尚无稳定code的原文行不冒充趋势支持。只读取observations，避免与reportRows、manualObservations重复计数。
- 保留原数字字面值、单位、比较符、临床日期/精确时刻、eventId/观测下标、sourceId和sourceLineIds；输出不修改输入。没有来源不伪造原图或行号。
- 性质和实例时区隔离；缺少所需元数据、未知schema、无偏移时刻、临床日期与时刻不符明确报错。没有时间只保留日期，不猜时分。旧schema不获得伪注入的v2时刻/比较符。
- 单位依据正式记录`knownUnit`白名单。所有不同单位分组，即使可能可转换也不跨组连线或计算；特别保留合法的血糖mg/dL。未知单位/无效数值留在INVALID点，不作为精确值。
- 同日多次都保留：精确时刻可排序；同一时刻（含不同时区偏移表示同瞬间）重复为冲突；当天任一日期级读数导致多次排序不确定时，当天均提示冲突。不使用三规则的“当日最大体温/最新值”选择丢点。
- `<`、`<=`、`>`、`>=`为BOUND，保留界限，不参与精确折线或差值。最新点无效/冲突时latest为null，不静默退到旧精确值。差值使用原Decimal，零前值不算百分比。
- dates为本页实际检查日期，不是每日补齐网格。某检查日期该指标缺失即断段，不填零/前值/插值；没有检查的自然日不凭空补点。跨已知缺项不计算相邻差值；分页之外不推测。
