# Demo 用户测试方案 V1.1｜当前功能对齐建议稿

适用版本：当前本机R26。此稿依据聊天正文修订；所给PDF路径暂未找到，未对PDF独有表格签收。测试负责人填好隐私安排和有效测试入口后可转成对外版本，不要把这份工程说明直接当家长邀请文案。

## 1. 本轮测试目标

观察患者或照护者能否独立完成：选图片并识别→核准内容→保存→找回原图和记录→理解三套参考规则的结果和缺项→比较上次、本次→准备问诊卡→理解本机保存和备份。

本轮不测试个人稳定期基线、两次发病轨迹对齐、所有指标的趋势图、内置AI问诊或临床诊断准确率，因为当前版本没有这些完整能力或尚无相应临床签收。现有趋势图仅MS评分；规则变化不等于风险升降。

稳定期基线和既往发病比较保留为未来需求访谈，明确告诉参与者“目前尚未提供”。不让参与者寻找不存在的入口，也不把未体验算低分。

## 2. 测试前准备

- 一份版本相同的测试入口。目前仅Mac本机 `http://127.0.0.1:18791/`，公网未恢复；这个地址不能发给远处参与者当在线链接。外部招募前由负责人另行确认可用入口和访问期，不沿用过期二维码。
- 先做3人小范围预试，验证步骤、时长和问题是否能听懂，再安排后续小样本。优先实际管理化验单的照护者；不强制收集既往MAS经历。
- 默认提供虚构或充分去标识的标准样张、对应人工核对表；涉及真实资料时单独说明授权和在线上传边界。开发与自动化测试不混入本人正式记录。
- 统一JPG/PNG、每张≤2MB，保持清晰。当前本机可保存≤8MB图片，但在线识别门槛不同；PDF/HEIC先转换。样张类型分开记，不能把某一种版式成功推广为所有报告成功。
- 准备一份缺少部分规则输入的样张。需要演示完整MS评分或两次对照时，再给日期明确、输入足够的虚构记录；真实上传响应与固定回放分别记录，不预填结果冒充识别。
- 截图/录屏自愿、另行同意。发放说明前填好负责人、访问范围、保留期限和撤回渠道。录制范围避开身份信息、密码、试用码及其他App。未同意录屏的人仍可完成体验。

## 3. 体验任务与观察记录

先不教具体按钮，让用户试做；卡住先记位置，再按需要协助。涉及错误风险时及时停止误用并说明，不能为了“无引导”放任用户据测试结果延误就医。

| 任务 | 给参与者的话 | 观察员检查；不提前展示答案 |
| --- | --- | --- |
| A 录入一份报告 | “请把这份报告记下来，保存前按原图核对内容。” | 能否分清选图和上传；是否主动同意上传；看到全部项目和待补项；能改名称、值、单位、参考范围和日期；逐项核对与最终确认；未确认无正式记录 |
| B 找回记录和原图 | “请找到刚存的记录，看看是否有漏掉或写错的内容，并找到原图。” | 项目数量与修正值、来源原文/原图是否保留；不把OCR原文行数与检验项目数混淆；关闭测试页面重开后仍可找到；跨浏览器不应当作自动同步 |
| C 看参考结果和变化 | “请看三张卡，选一张说说它用了哪些信息、还有哪些不清楚。再找一下上次和本次的变化。” | 理解满足/不满足/未知与缺项；能找到来源；知道上次未必稳定期；只有MS评分画历史图，缺项断开有说明；不评价疾病诊断是否正确 |
| D 准备就诊内容 | “下次见医生前，请选几条状态，整理一份能给医生看的内容。” | 选状态→给话术；可修改、复制、下载；不需要AI账户。愿意者再看“问AI”，知道需自己去外部工具粘贴发送，产品不自动调用 |
| E 备份和恢复 | “如果换浏览器前想留下记录，您会怎样做？” | 能找到本机备份，知道.ptds加密及密码用途、原图包含、问诊卡另下载。恢复只在负责人准备的空白测试环境演示，核准记录与来源；不得清空参与者已有真实资料 |

核心体验可先完成A–C，D、E按场次明确安排。未安排的任务不进入完成率分母；不能据此宣称全部闭环已由每位参与者完成。

每个任务记：匿名测试编号、产品版本、iPhone/iOS或其他浏览器版本、任务是否安排、开始/结束、独立完成/指导后完成/未完成、卡点、帮助内容、错误及用户原话。过程记录由观察员填写，避免把所有操作细节再塞进问卷。设备型号与版本即可，不收设备唯一标识。

OCR额外记录：报告项目总数、候选项数、漏项、名称/数值/单位/参考范围/箭头的错项、待补项数、人工修改数、保存后是否仍一致，以及真实调用/固定回放、等待时间和失败情况。区分供应商识别错误、版式配对错误、用户核对困难。日期是手动核对任务，不混进自动日期识别准确率。无单位的比值按原件记“不适用”，不算漏单位。不要用主观评分或供应商置信度直接代表客观准确率。

## 4. 体验后精简问卷（12题）

问卷说明建议：

> 感谢参与sJIA·MAS记录工具的测试。请按实际体验回答，没体验的可跳过。我们主要想知道哪些地方不好用、不好懂；参考结果不能代替医生判断。问卷不要求姓名、电话、证件信息或化验单原文，请勿填写密码或访问码。反馈由【负责人】在【期限】内用于改进，仅【范围】可访问；可通过【途径】申请撤回或删除。截图、录屏需另行同意。预计时间在预试计时后填写。

Q1. 您主要以什么身份体验？【单选、可不答】
- 患者本人
- 家属或主要照护者
- 其他
- 不愿回答

Q2. 完成这次任务，您觉得操作是否方便？【单选】
- 非常方便／比较方便／一般／比较困难／非常困难
- 主要任务未完成，无法评价

Q3. 哪些地方让您卡住或需要帮助？【多选】
- 分不清“选图片”和“上传识别”
- 上传或识别失败、等太久
- 漏了项目，或名称、结果、单位、参考范围不对
- 不会补填空结果，或不会改识别内容
- 找不到或不会填写记录日期、采样时间
- 不明白逐项核对和最后保存的区别
- 看不懂三张卡或变化信息
- 不清楚问诊卡和“问AI”怎么用
- 备份或恢复不好操作
- 字太小、按钮难找或页面显示有问题
- 其他：____
- 没遇到问题【与问题选项互斥】
- 未体验主要任务【互斥】

Q4. 对照原图后，您觉得识别结果怎样？【单选】
- 已逐项对照，没发现错误
- 发现少量需要修改的内容
- 发现多处需要修改或补填
- 大部分需要重填
- 上传或识别失败
- 没有逐项对照，无法判断
- 未体验在线识别

Q5. 对照原图、检查并修改内容是否方便？【单选】
- 非常方便／比较方便／一般／比较困难／非常困难
- 未体验核对修改

Q6. 三套参考规则显示的结果、依据和缺少的信息，您能看懂多少？【单选】
- 全部／大部分／一部分／很少／基本看不懂
- 未查看这些内容

Q7. 如果页面写着“不满足条件”或“资料不够”，您会怎样理解？【单选，不提前解释答案】
- 据此就可以排除MAS，不需要再结合其他情况
- 单凭这个结果还不能排除风险，需要结合症状和医生判断
- 说不清楚
- 未看到这些结果

Q8. 页面比较的“上次”是否一定代表病情稳定时的水平？【单选，不提前解释答案】
- 一定是
- 不一定，只是可用的上次记录
- 说不清楚
- 未体验变化对照

Q9. 本次哪些功能对您有帮助？【多选，仅列现版】
- 报告识别后核对并保存检查项目
- 找回记录、原图与识别原文
- 三套参考规则的结果、依据和缺项说明
- 规则输入的上次/本次对照
- MS评分历史变化【未体验可不选】
- 选状态并整理、修改或下载问诊卡
- 为自己的外部AI准备提示词【可选体验】
- 加密备份与恢复
- 暂时没觉得有帮助【互斥】
- 体验不足，无法判断【互斥】

Q10. 如果后续持续完善，您愿意日常使用吗？【单选】
- 非常愿意／比较愿意／不确定／不太愿意／完全不愿意

Q11. 您遇到的最大问题是什么？【选答，不填报告原文或身份信息】

Q12. 如果优先改一个地方，您最希望改什么？【选答，只写一个】

Q7/Q8是理解校验，不计满意度；观察员在答完后再解释。回答错误应记录为产品解释/体验问题线索，不能归咎患者，也不能说问卷证明其临床知识合格。

## 5. 访谈补充（按需，不全部必问）

先问：您刚才停住时在想什么？哪一步与平时习惯不同？您认为选图后、上传识别后、保存后，资料分别在哪里？问诊卡会自己发给医生或AI吗？如果清掉网站数据会怎样？备份里有没有尚未完成的录入或问诊草稿？记录原话再解释。

未来需求另开一段，并明确尚未实现：

> 将来如果可以比较稳定期水平或过去一次发病过程，哪一个最能帮助您？请举一个您会使用它的实际场景。若只能先做一种，希望先解决什么？

再按需追问差值、幅度、时间点或轨迹；不要先展示一串“好功能”引导全选。MAS经历、平时记录方法只在确需分层、单独说明用途且自愿时收集；不与可识别报告一起收集。

## 6. 结果如何用于迭代

- 按任务报“独立完成人数/实际尝试人数”，另列指导完成、失败与未安排，不将跳过者按失败计分，也不悄悄剔除实际失败。
- 主观问卷、客观字段正确性、理解错误、缺陷列表分开报告；不合成一个“安全有效百分数”。样本很小时展示人数和案例，不将平均分推广到患者总体。
- 先修会阻断任务、丢数据、错配数据或绕过确认的问题；把缺项当无风险等理解错误单独列优先项。偏好和未来功能进入需求池，不据问卷自动扩大当期开发范围。
- 保存和恢复的确认门槛、来源绑定等由工程测试佐证；手机总内存、真实低空间、临床规则核验和本人验收分别留证，不能由满意度高代替。
- 试测后由负责人明确后续测试范围与是否扩大招募；这份方案本身不恢复公网、批准临床预警或替任何人签收。
