# R34 修复说明：损坏名称不得生成错误指标趋势

R33独立审计发现P1-001：名称匹配器把RBC RBC、PCTPCT等重复OCR文字当作正常指标，跨日期生成了错误差值。正式A2未采用R33，所以本轮只修新隔离候选，不改正式源码或服务。

根因不只新展示目录的循环匹配：原显示身份第一分支调用的metricCode也会循环消费同一指标的多个别名。因此本轮统一两条展示身份分支，以完整规范化名称集合匹配。合法双语名称用catalog中有限的DISPLAY_BILINGUAL完整字符串登记；没有递归分词、任意重复或动态排列组合。所有登记名称仅用于显示，不扩医学规则或存储字典。身份版本report-metric/2，旧已存原值/原名/来源不改。

模块只有identity.js与catalog.js。无锁/新Store/DB/网络/后台任务；查表为固定大小集合、报告页仍最多50份，原投影/显示分页和四档规模门槛保留。无法识别的损坏名称继续可见，带原名核对提示，与正确指标分组；不猜测修复原文。比如两份合法RBC的4.50→5.50显示差1，随后RBC RBC=6.00独立显示，不能贡献另一个0.50或1.50。

新增测试先在未修复R33上实际失败，保留identity-before01.log；再修同根因，涵盖显示目录和canonical目录全部登记别名的重复/三重/空格重复，以及有限双语对、跨项目/前缀/剩余字符和数字前缀反例。保留原T1/三规则/录入/恢复测试，不改旧金样。浏览器新增显式虚构自动操作员的三个Service正常确认保存，核对页面两组、原文来源/返回、恢复与不同PID读回；原30组60点路径仍保留。去修复变异必须真实制造错误归并并被业务断言杀死。

独立完整门槛old-stage加载问题有另外的可复现工具原因：Server构造时会resolve根路径，但测试直接赋值root时绕过规范化；/tmp解析后为/private/tmp，严格路径保护因此返回404。自有最小HTTP反例实际得到初始200→未规范化切换404→规范化切换200。修复仅在tests/report_upgrade.py及tools/test_upgrade.py的根切换加resolve(strict=True)，不放宽产品网关，不改旧R27冻结字节。完整门槛使用/tmp新输出目录，实际覆盖该条件。首页特殊路径可能仍返回200，但其模块请求被拒，所以原错误表现为模块加载失败。原独立失败保留，不倒填为独立成功。
